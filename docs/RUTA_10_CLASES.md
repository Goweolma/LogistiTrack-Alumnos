# Ruta de trabajo — 10 clases

| Día | Meta del equipo | Evidencia |
|---:|---|---|
| 1 | Levantar base, asignar ramas e Issues | Base verde y primer PR documental |
| 2 | Cerrar contratos y modelo de datos | Contratos aprobados |
| 3 | Crear y consultar pedidos | API + PostgreSQL |
| 4 | Reservar inventario por Kafka | Dos servicios comunicándose |
| 5 | Preparar y despachar pedido | Backend integrado |
| 6 | Crear interfaz y seguimiento | Flujo visible en navegador |
| 7 | Probar caídas y duplicados | Evidencias de recuperación |
| 8 | Automatizar pruebas y corregir | Smoke test final |
| 9 | Terminar manual y ensayo | Release candidate |
| 10 | Demostración y PR a `main` | Tag `v1.0.0` |

## Entrega mínima diaria

Cada integrante deja al menos un commit útil o una revisión documentada. Un
commit que solo cambia espacios o nombres no cuenta como avance funcional.
